Content management

Change what the world sees — no developer required.

Every section on every public page has an editable label, heading, and description stored in the database. Go to Admin → Section Headers Management and click any section to edit. Changes appear on the website immediately after clearing the cache.

Reviews

Chapter 7 · Your inventory

Room management

From type to individual unit — every room is tracked, status-aware, and booking-ready.

Room Types

Manage at Admin → Room Management. Each type has: name, description, photos (gallery-linked), base nightly rate (MWK), capacity (adults + children), amenities list, featured toggle (homepage), and active/inactive toggle.

Individual Rooms

Each physical room unit has its own record at Admin → Individual Rooms: room number, floor, type assignment, current status, and notes. Status flows: available → occupied → dirty → cleaning → inspected → available. Out-of-service rooms are removed from bookable inventory immediately.

Room Dashboard

Admin → Room Dashboard shows a live colour-coded grid of every room on every floor. Reception uses this for an instant hotel snapshot at any moment of the day.

Maintenance

Log a fault at Admin → Room Maintenance. Set priority (urgent / high / medium / low) and assign to a technician. When a room is set to out-of-service it is automatically removed from bookable inventory until cleared by maintenance.

Blocked Dates

Block specific dates for a room or the whole hotel at Admin → Blocked Dates. Four block types: manual, maintenance, event, full. Blocked dates prevent new bookings. Existing bookings are unaffected.

⚠

Always set room status to out-of-service via Maintenance before physically locking a room for renovation — this ensures it drops out of online availability.

Chapter 10 · Money

Payments & invoicing

Every transaction — accommodation, F&B, room service — flows into one folio per guest, settled once at checkout.

Payment methods

MethodNotes
CashEnter tendered amount; change calculated automatically.
CardLogged as card payment; amount reconciled at EOD.
Mobile MoneyAirtel Money & TNM Mpamba — first-class, not an afterthought.
Bank transferReference number stored against the payment record.
ComplimentaryManagement override with required notes/reason.

Add payments at Booking Details → Add Payment. Partial payments are supported; the outstanding balance updates in real time.

Invoicing

Invoices are numbered sequentially INV-YYYY-NNNNNN and can never be reused or deleted. Each invoice shows itemised accommodation + F&B charges, applies VAT and tourism levy according to your VAT pricing mode (added on top, or already included in the price), is generated as PDF server-side, can be emailed to the guest directly, and is archived permanently under Admin → Invoices.

The Invoices page shows a receivables aging panel. Outstanding invoices are bucketed by age since the invoice was created (0–30 days, 31–60, 61–90, 90+). The Outstanding KPI shows only money owed by guests — pending refunds (money owed to guests) are excluded to prevent misreading your receivables position.

Refunds & Credit Notes

Process cash refunds at Admin → Payment Refund. Enter amount, reason, and method. The accounting dashboard records the refund against the original payment. Refunds do not auto-cancel bookings — cancel separately if needed.

When cash cannot be returned immediately (early checkout, goodwill, overpayment), issue a Credit Note from Admin → Credit Notes. The CN carries a sequential number (CN-YYYY-NNNNNN), a face value, and an optional expiry date. It can be applied to any future booking; when applied, the booking balance decreases and the CN balance decrements atomically. Set credit note expiry months in Booking Settings (0 = no expiry).

ℹ

The server validates all prices. A guest cannot tamper with totals in the browser — every price calculation happens in PHP, never in JavaScript.

Chapter 12 · The menu

Menu management

Build and update your menu entirely from the admin — changes are live on the POS and public website immediately.

Structure

Manage at Admin → Menu Management. Items are organised into categories (Starters, Mains, Desserts, Cocktails, Wines, Coffees, etc.). Each item has: name, description, price (MWK), category, routing (Kitchen / Bar / Coffee), optional photo, available toggle, and featured toggle.

Chapter 13 · In-room dining

Room service that pays for itself

Every breakfast tray, late-night snack, and bottle of wine — billed cleanly to the right room, automatically.

  1. Reception or room-service runner opens the Room Service Dashboard and taps New Order.
  2. Select the room number from the live occupied-rooms list.
  3. Add items from the full menu. Routing fires to KDS (food), BDS (drinks), or CDS (coffee) automatically.
  4. The guest folio is debited the same instant — VAT and tourism levy applied.
  5. Runner taps Mark Delivered when the tray arrives at the room.
  6. At checkout, room-service charges appear as individual line items on the final invoice.
ℹ

A void on a room-service order reverses both the stock deduction and the folio charge in a single atomic transaction — no partial corrections needed.

Ingredients

Admin → Stock Ingredients. Master catalogue: name, unit (ml, g, each), par level, cost price, and supplier. Par levels trigger reorder alerts on the stock dashboard.

Recipes

Admin → Stock Recipes. Link each menu item to ingredient quantities. Sell a cocktail — spirit, mixer, and garnish all decrement. No recipe = no automatic deduction.

Stock Orders

Admin → Stock Orders. Raise a purchase order to a supplier. Status tracks: draft → submitted → partially received → received.

Stock Receipt (GRN)

Admin → Stock Receipt. Log quantities received against the PO. The system updates on-hand stock levels and recalculates average cost prices.

Batches

Admin → Stock Batches. Track batch numbers and expiry dates for perishables. Alerts flag approaching expiry before wastage occurs.

Wastage

Admin → Stock Wastage. Record spoilage, breakage, or theft. Each record carries a reason code and unit cost of the loss. Wastage is included in the variance report.

Stock Count

Admin → Stock Count. Walk the bar or kitchen with a tablet, key in physical counts. The system flags variances above 5% in red.

Variance Reports

Admin → Stock Reports. Item-by-item variance: theoretical vs physical. Export as CSV. Consistently high variance on one item = recipe error, measurement problem, or shrinkage to investigate.

Chapter 19 · Protection

Security, audit & backups

Built-in security

  • Every login, password change, and role change is logged.
  • 5 failed logins → 15-minute account lockout.
  • 10 failed attempts from one IP → 1-hour IP block.
  • Passwords stored as bcrypt hashes — never plain text.
  • Reset tokens: one-use, hashed, expire after 1 hour.
  • All database queries use prepared statements — SQL injection is architecturally impossible.
  • All forms use CSRF tokens — cross-site request forgery is blocked.
  • Security headers (CSP, X-Frame-Options) sent on every response.
  • Rate limiting on booking form: 5 attempts per 10 minutes per IP.
  • Public API endpoints protected by API key authentication.

Audit trail

  • Every booking status change: who, when, from what to what.
  • Every payment add/refund: user ID and timestamp.
  • Every housekeeping status transition logged.
  • Every maintenance request, assignment, and resolution.
  • Every stock receipt, count, and wastage entry.
  • Offline POS actions queued during load shedding and replayed on reconnect — nothing is lost.
  • All system events viewable at Admin → System Logs.

Backups

Run on-demand at Admin → Backup Management. Produces a compressed .sql.gz file. Download and store off-site monthly. The restore function lets you select any backup and rebuild from it. Admin-only access.

Chapter 20 · Under the hood

System administration

Cache Management

The system caches DB queries for speed. If a content change does not appear on the website, go to Admin → Cache Management and clear the page cache. Full clear refreshes everything in under 1 second. Caches rebuild automatically on the next page load.

✓

80% of “the website hasn't updated” issues resolve with a cache clear.

System Logs

Admin → System Logs shows the event log: info, warning, and error entries from every module. Filter by date, severity, or source. The most recent error is at the top of the filtered list. Logs are also written to logs/system-events.log on the server for developer access.

API Keys

Manage at Admin → API Keys. Keys protect the public availability and booking API endpoints. Generate a new key when onboarding a third-party integration (channel manager, OTA). Revoke keys that are no longer in use.

Offline Log

Admin → Offline Log shows every POS or KDS action queued during a network outage. Verify successful replay after connectivity returns. Failed replays are flagged for manual reconciliation before end-of-day.

Visitor Analytics

Built-in analytics at Admin → Visitor Analytics — no Google Analytics or third-party tracking. View daily/weekly/monthly visitors, top pages, device types, and the booking conversion funnel. GDPR-friendly: no external cookies.

Health Check

Run a full system diagnostic from the server: php scripts/health-check.php. Verifies database connectivity, file permissions, SMTP, and table integrity. Run after any server migration or major update.

Chapter 22 · When things go wrong

Emergency procedures

⚡ Load shedding / power cut

  • POS and KDS switch to offline mode automatically — orders queue locally on the device.
  • Staff continue taking orders on the POS with no stoppage.
  • On power return, the system replays all queued orders automatically.
  • Verify successful replay in Admin → Offline Log.
  • Any failed replays require manual entry via POS before EOD reconciliation.

🌐 Internet outage

  • POS runs offline as above — no internet required for F&B operations.
  • Admin panel is inaccessible from outside the LAN without internet.
  • On recovery, the website resumes accepting bookings immediately.
  • Check Tentative Bookings — any forms submitted during outage may have queued.

🖥 Admin panel returns 500 error

  1. Check logs/error.log on the server for the most recent error.
  2. Run php scripts/health-check.php for a full diagnostic.
  3. Try Cache Management → Full Clear if any page is accessible.
  4. Contact the developer with the last 50 lines of logs/error.log and the timestamp.

🔒 Locked admin account

  • Wait 15 minutes for automatic unlock (5-attempt lockout).
  • Wait 1 hour for automatic IP unblock (10-attempt IP block).
  • Use Forgot Password to reset via email if the account is accessible.
  • If the owner account is completely locked, the developer can reset via server CLI.
  • Never try to brute-force your own account — it compounds the lockout.

💳 Payment discrepancy

  • Check Admin → Payments — filter by date and method.
  • Compare POS shift report with the cash drawer count.
  • Check Admin → Order Lifecycle for any voided or reversed orders.
  • Run the Accounting Dashboard for a clean figure by payment method.
  • Document discrepancies and investigate before reconciling.

📦 Stock level wrong

  • Run a manual stock count for the affected items.
  • Check the wastage log — unreported breakages cause system drift.
  • Verify the recipe for the affected item — a quantity error compounds over every sale.
  • Log any corrections as wastage with reason count adjustment.
