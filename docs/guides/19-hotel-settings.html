Rosalyns Beach Hotel All guides Admin reference

Hotel Settings

Hotel Settings is one long page of cards. Each card controls one part of how Rosalyns Beach Hotel takes bookings, charges money, produces documents and sends email. This guide goes through the cards in the order they appear on the page.

Who uses it
Manager or owner. Staff do not need this page for daily work.
Where to find it
Admin menu → Settings → Hotel Settings (/admin/booking-settings.php)
Permission needed
Hotel Settings to open the page and change most cards. Three kinds of setting also need Change VAT & refund settings (marked below). The email and PDF wording is a separate page that needs Edit message templates.
Only shown when
Most cards are only shown when the Bookings & Reservations module is switched on in Settings → Modules. With it off, the page is called Business Settings and shows only Frontend Maintenance Mode, Email Configuration, Service Modules and PWA Install Banner. The cards that need the module are marked below.

What is on the screen

  • The heading Hotel Settings and a Back to Dashboard link.
  • A Jump to bar with links: Maintenance, Booking status, Advance booking, Refunds, Hotel details, References, Branding, Tentative, Tourism levy, Email, Notifications, Service modules, PWA, and Email templates → (opens the separate Email Templates page).
  • After you save, a green box at the top shows the result. A red box shows an error. Each card has its own save button, and a save button saves only its own card. Anything you typed in another card is not saved.

Always click the save button on the card you changed before you scroll to another card. A card's save button saves that card only.

Frontend Maintenance Mode

This card shows the current state: Frontend is Live ("Public pages available") or Frontend is In Maintenance ("Public pages blocked (admin stays online)").

Fields

  • Enable Full Frontend Maintenance Mode (tick box). It saves the moment you tick or untick it. There is no save button and no question first.
  • Maintenance Message (text area, up to 1,000 characters). Shown to every visitor while maintenance mode is on. If you save it empty, the standard text is used: "Our website is temporarily unavailable while we complete scheduled maintenance. Please check back shortly."

What people notice

  • Guests who open any page of the public website see the maintenance page with your message. Booking and all other guest pages are blocked.
  • The admin, including the POS and the stations, keeps working. Admin and API addresses stay reachable.

Messages

  • Ticking: "Frontend maintenance mode enabled. Public pages now show the maintenance page."
  • Unticking: "Frontend maintenance mode disabled. Public pages are live again."
  • Saving the message with Save Maintenance Message: "Frontend maintenance message updated successfully!"

Ticking the box takes the whole guest website offline straight away. Untick it as soon as you are finished.

Booking System Status

Only shown when the Bookings & Reservations module is on. The card shows Booking System is Enabled (Active) or Booking System is Disabled (Inactive).

Fields

  • Enable Online Booking System (tick box). It saves the moment you tick or untick it.

What people notice

The note on the card says it: "When disabled, all booking forms, buttons, and widgets will be hidden. Guests will see a message instead of booking options."

Messages

  • "Booking system enabled successfully!"
  • "Booking system disabled successfully!"

Disabled Mode Settings

Below the switch is the Disabled Mode Settings box. It decides what guests see on the booking page while online booking is off. You can set it before switching booking off. (While booking is off, a yellow Booking System Disabled box also appears, and its Configure Disabled Message link jumps to these settings.)

  • Action When Disabled (list): Show Custom Message, Show Contact Information or Redirect to URL. The first two look the same to guests: your message plus Call Us and email buttons with the hotel phone and reservations email. Redirect to URL sends guests to the page you give instead.
  • Redirect URL (only for Redirect to URL). Must start with http://, https:// or a single / (for example /contact). Up to 500 characters.
  • Custom Message (up to 1,000 characters). You can type [phone], [email] or [contact info] and the hotel's main phone and reservations email are put in for you.
  • Save button: Save Settings. Message: "Disabled mode settings updated successfully!"

Errors: "Redirect URL is too long (500 characters maximum)." and "Redirect URL must start with http://, https:// or a single /."

Advance Booking Configuration

Only shown when the Bookings & Reservations module is on.

Fields

  • Maximum Advance Booking Days: a whole number from 1 to 365. Default 30. Guests can only book up to this many days from today.

What guests notice

The date pickers on the booking form only allow dates inside this window. The system also refuses bookings beyond it, and guests see a message about the booking window.

Save button and messages

  • Save Changes → "Maximum advance booking days updated to N days successfully!"
  • Below 1: "Error: Maximum advance booking days must be at least 1". Above 365: "Error: Maximum advance booking days cannot exceed 365 (one year)".

Refunds & cancellations

Only shown when the Bookings & Reservations module is on. It shows Current handling and four groups of choices. Everyone with Hotel Settings can see them. Only people with Change VAT & refund settings can change them; for everyone else the choices are greyed out, there is no save button, and the card says "You can view these rules. Only users with the "Change VAT & refund settings" permission can change them."

Fields (choose one in each group)

GroupChoices and what they do
When a room booking is cancelled Void the bill and refund everything paid: the booking owes nothing and the full net amount paid is refunded automatically.
Void the bill, keep payments as guest credit: the booking owes nothing but no refund is made automatically. The money paid shows as owed back to the guest, for staff to refund or issue a credit note.
Charge the first night, refund the rest: the guest is charged the first night (nightly rate including its VAT and levy share); the bill is reduced to that amount and the rest of the net paid is refunded.
When a guest cancels online Staff approve the refund: the refund is queued as pending until staff settle it.
Refund immediately: the refund is marked completed the moment the guest cancels.
When a conference, event or gym account is cancelled Keep payments as credit: the bill is voided and money paid stays as credit owed back; staff refund it manually.
Refund everything paid: the net amount paid is refunded automatically when the account is cancelled.
How refunds are paid out Always to the original payment method: refunds go back the way the money came in and staff cannot change the method.
Staff choose on the refund screen: the refund screen starts on the original method but staff may pick another.

What people notice

The new rules apply to every cancellation made after you save. Bookings already cancelled are not changed. Charges already posted to a booking's folio stay billable.

Save button and messages

  • Save Refund Settings → "Refund and cancellation settings saved."
  • "You do not have permission to change refund and cancellation settings."
  • "Invalid refund or cancellation option."

Each change is written to the system log with the person's name, the old choices and the new choices.

How to change the details

  1. Open Hotel Settings and go to Hotel details & policies (or click Hotel details in the Jump to bar).
  2. Change the fields you need. You can change fields in several groups in one go.
  3. Click Save Hotel Details.
  4. You will see "N setting(s) saved.", or "No changes to save." if you changed nothing.

If any field is wrong, nothing at all is saved. You see the problem field with its rule, then "Nothing was saved." Fix it and save again. Examples of the rule text: "Check-in from: a time such as 2:00 PM or 14:00.", "Star rating (0 = not rated): a whole number from 0 to 5.", "Website address (used in emails, documents and password-reset links): the full address of the site, e.g. https://www.yourhotel.com (no ? or #).", "Account number: letters, digits, spaces and dashes only."

Every change is written to the system log, with the old and new value.

Tentative Bookings

Only shown when the Bookings & Reservations module is on. The card shows Tentative Bookings are Enabled or Disabled. A tentative booking is a hold on a room with no payment up front.

Fields

  • Allow Tentative (Hold) Bookings (tick box).

The card also says how many hours a hold lasts (48 hours unless the hotel has set another value). The reminder time is the Tentative hold reminder field in Hotel details & policies.

What people notice when it is switched off

  • The Tentative Booking card on the public booking page is removed.
  • The Tentative (hold) option on the admin booking forms is removed.
  • Tentative bookings that already exist stay as they are. The tentative email templates stay set up for later.

How to change it

  1. Tick or untick Allow Tentative (Hold) Bookings. The button label changes to Save — Enable Tentative Bookings or Save — Disable Tentative Bookings. When you untick it, an orange box says "Disabled: Guests cannot create new tentative holds. Existing holds in the system are unaffected."
  2. Click the button. If you are disabling, the browser asks "Disable tentative bookings? Guests will no longer be able to place tentative holds from the public booking page or admin forms." followed by "Existing tentative bookings in the system will not be affected." Click OK.
  3. You will see "Tentative bookings enabled — guests can hold dates without immediate payment." or "Tentative bookings disabled — only standard bookings will appear on the website and admin forms."

When nothing has been changed the button reads Save — Keep Enabled or Save — Keep Disabled.

Tourism Levy / City Tax

Only shown when the Bookings & Reservations module is on. It needs Change VAT & refund settings to change. Without it, saving shows "You do not have permission to change the tourism levy." The page does not grey the fields out, so the message only appears after you click save.

Fields

  • Enable Tourism Levy (tick box).
  • Tourism Levy Percentage (%): a number from 0 to 100, with up to 2 decimals (for example 1.5). The card says common values are 1% to 5%.

What people notice

  • The levy is worked out as (room rate + child supplement) × (levy % / 100) and added to new bookings. Existing bookings are not changed.
  • The booking page shows a hint "Includes X% Tourism Levy".
  • Invoices show the levy as a separate line.

Save button and messages

  • Save Tourism Levy Settings → "Tourism levy enabled at N% successfully!" or "Tourism levy disabled successfully!"
  • "Error: Tourism levy percent cannot be negative" and "Error: Tourism levy percent cannot exceed 100%".

Make sure the percentage matches the local tourism tax rules before you switch the levy on.

How to send a test email

There is no test button on this card. Test emails are sent from the Email Templates page:

  1. Open Admin menu → Settings → Email Templates (needs Edit message templates).
  2. Choose a template and make a preview.
  3. Type a valid email address in the test box and click Send. You will see "Sent to <address>!". The subject starts with [TEST].

The Automated Emails page also has a Send test to me button that sends sample emails to your own admin email address (see below).

If Development Mode (Preview Only) is ticked, no guest gets any email, and the test email will not arrive. Untick it when the hotel is ready to send real email, and save.

Booking Notification Email

Only shown when the Bookings & Reservations module is on. It says who inside the hotel is told about new bookings, and sets the reminder and review emails to guests. Save with Save Notification Email.

Fields

  • Notification Recipient Email: a valid email address. New booking notifications go here first; if it is empty the Admin Notification Email from Email Configuration is used.
  • Booking Notification CC Emails: optional list of addresses separated by commas, up to 1,000 characters. Copied on all new booking notifications.
  • Send pre-arrival reminder email to guests (tick box) and Days before check-in (whole number 1 to 14; sent once per booking). A number outside the range is changed to the nearest allowed number.
  • Send post-stay review request email to guests (tick box) and Days after check-out (whole number 0 to 14; 0 means the day of check-out; sent once per booking).

Messages

  • "Booking notification email updated successfully!"
  • "Error: Booking notification email address is invalid", "Error: One or more booking CC email addresses are invalid", "Error: Too many CC addresses (1000 characters maximum)".

Where the wording and other hotel details live

  • Email and PDF wording (subject lines, body text, invoice and quotation layouts) is on Admin menu → Settings → Email Templates, and needs the permission Edit message templates. The list of tags you can put in a template is in Email template tags. This page, Hotel Settings, does not edit any wording.
  • Automated Emails (Admin menu → Settings → Automated Emails, /admin/automated-emails.php, permission Hotel Settings): the master switch for automatic jobs, the overdue payment reminder stages, the run interval, a test-recipient box and a Send test to me button (see Automated Emails). If the Test recipient box has an address in it, every automatic email goes to that address instead of to real guests, and a yellow TEST MODE bar shows at the top. Leave it empty in normal use.
  • Footer (Admin menu → Website → Footer, /admin/footer-management.php, permission Footer Management, needs the Website & CMS module): this is where the hotel name (Site Name), tagline, logo, main Phone Number, Email Address, Address, Working Hours, the social media links (Facebook URL, Instagram URL, Twitter / X URL, LinkedIn URL) and the copyright text are set. Saving shows "Site and footer settings saved." The site name cannot be empty: "Site name is required."

Automated Emails (reminders that send themselves)

Admin menu → Settings → Automated Emails (/admin/automated-emails.php), permission Hotel Settings. Reminders go out by themselves while people use the website or the admin. No cron job is needed. At most once every Run interval minutes (15 by default), the next page someone opens starts a run in the background after their page has loaded, so nobody waits for it.

The Status box

  • The Status box shows whether the Master switch is ON, the Last run time, and each job's state: not_due (nothing to send yet), off (switched off), or what it sent, for example "sent 0 of 1 due". The master switch itself (under Settings) turns ALL automatic jobs on or off, the nightly backup included.
  • Run now runs every switched-on job straight away and reports per job, for example "Run complete. Overdue payment reminders: sent 2, checked 14 · …". "Nothing ran (…)" gives the reason, for example the master switch is off.
  • A yellow TEST MODE bar means the Test recipient box is filled in: every automatic email goes to that address and real guests are not contacted. Clear the box to go live.

Settings

  • Reminder stages (days overdue, up to 3): default 1, 3, 7, a reminder 1, 3 and 7 days after the due date.
  • Payment terms for events / gym / conference (days): default 7. How long after the invoice money counts as due.
  • Stop chasing after (days overdue): default 30.
  • Run interval (minutes): 5 to 1440, default 15.
  • Test recipient (leave EMPTY in production): see TEST MODE above. An address that is not valid is cleared when you save.
  • BCC the hotel (admin notification address) on payment and quotation reminders: a hidden copy of those reminders goes to the hotel.
  • Tick or untick each job, then click Save settings ("Automated email settings saved.").

Testing and the activity log

  • Email templates lists each automatic email (Payment reminder 1 friendly, 2 firm, 3 final; Quotation expiry reminder; Tentative hold reminder and expired; Pre-arrival reminder; Post-stay review request; Gym membership renewal) and whether it uses a template you can edit in Email Templates or Built-in wording. Click Send test to me on a row: that email is sent with sample data to your own admin email address only, and nothing is recorded. If your account has no email address you see "Your admin account has no valid email address to send the test to."
  • Recent activity (last 100) lists every automatic email: When, Job, Account, Stage, Recipient and Status (sent, failed with the reason underneath, or skipped, for example demo bookings). Each reminder stage is sent once per booking or account, never twice. A failed line such as "Invalid address: (From)" means the sending address in Email Configuration is missing or wrong.
  • The wording of each email is edited in Email Templates.

Rules the system enforces

  • Each card saves on its own. A save button never saves another card.
  • Refund rules, document branding, tourism levy, and the payments fields and restaurant service charge in Hotel details need Change VAT & refund settings.
  • The Hotel details form saves nothing if even one field is wrong.
  • A changed booking reference prefix, tourism levy, refund rule or branding only affects new bookings and new documents. Existing ones are not changed.
  • Changes to refund rules, document branding, booking prefix, maintenance mode and hotel details are written to the system log with the person's name.
  • The page itself is kept available even when modules are switched off, because it is the only place email sending is set up.
