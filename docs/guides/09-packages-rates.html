Packages & Rate Plans

Add-on packages guests love, and dynamic pricing that optimises revenue automatically.

Audience Manager & admin Read time ~5 min Pages /admin/packages.php · /admin/rate-plans.php

Room Packages

Packages are add-ons a guest can select when booking — honeymoon extras, half-board meals, airport transfers, spa access, and more.

Creating a package

  1. Go to Admin → Packages (/admin/packages.php).
  2. Click Add Package. Fill in the name, short description, and inclusions (one item per line).
  3. Choose a pricing model:
    • Per night — multiplied by the number of nights in the booking.
    • Per stay — a flat charge regardless of duration.
    • Per person per night — multiplied by guest count × nights.
  4. Set the price, choose a Font Awesome icon (e.g. fa-heart, fa-plane), and assign a sort order.
  5. Tick Featured to promote it on the homepage packages section.
  6. Scope to All room types or pick specific types from the list. Guests only see packages valid for the room they are booking.
  7. Save. The system auto-generates a URL slug from the name.
Inclusions appear as a bullet list under the package title on the booking page. Keep each line short — one item, one line.

Editing & disabling packages

  • Click Edit on any package card. All fields are editable; the slug updates automatically if you change the name (existing booking links still work).
  • Toggle the Active switch to hide a package from guests without deleting it.
  • Set Sort order (lower number appears earlier), then save to control display sequence on the booking form.
Pricing model Best for Example
Per night Breakfast, dinner, airport pick-up on each day MWK 8,500 × 3 nights = MWK 25,500
Per stay One-off gifts: bouquet, champagne, early check-in MWK 35,000 flat
Per person per night Full board, guided activities, spa passes MWK 6,000 × 2 guests × 4 nights = MWK 48,000

Dynamic Rate Plans

Rate plans automatically adjust room prices at booking time based on season, demand, or booking behaviour — no manual discounting needed.

Creating a rate plan

  1. Go to Admin → Rate Plans (/admin/rate-plans.php).
  2. Click Add Rate Plan. Choose a plan type:
Plan type When it fires Typical use
Seasonal Stay falls within a date range Christmas / school holiday surcharge, low-season discount
Weekend Stay includes specific days of the week Friday–Sunday premium
Length of stay Minimum nights threshold is met 10% off 5-night stays, 15% off 7+ nights
Last-minute Booking made within X days of check-in Fill empty rooms at 20% off, booked < 3 days before
Early-bird Booking made at least X days in advance 5% off if booked ≥ 60 days ahead
Promotion Booking falls within an active promo window Anniversary sale, Valentine's special
  1. Set the adjustment: choose Percentage or Fixed amount and enter the value (negative for a discount, positive for a surcharge).
  2. Set the active date range — the plan only applies to bookings made OR stays falling within these dates (depending on type).
  3. Optionally restrict to specific days of the week, minimum/maximum nights, or room types.
  4. Set a priority number — higher number = higher priority when multiple plans match.
  5. Toggle Stacking to allow this plan to compound with others on the same booking, or leave it off to let the highest-priority plan win alone.
  6. Save. The plan is active immediately.
Review plans before peak season. If stacking is ON across multiple plans, discounts compound. Run a test booking to verify the final price before going live.

Managing existing plans

  • Edit the Priority value (higher number is evaluated first), then save.
  • Toggle Active to enable/disable without deleting.
  • Edit to change any field; changes apply to new bookings only (existing bookings are unaffected).
  • Delete removes the plan permanently; use deactivation instead if you want to reuse it next season.

How plans interact at booking

  1. System collects all active plans that match the booking's dates, room type, nights, and lead time.
  2. Plans are sorted by priority (highest number first).
  3. If the top-priority plan has stacking OFF, only that plan is applied.
  4. If it has stacking ON, the next-priority matching plan is also applied, and so on down the stack.
  5. The adjusted price is shown to the guest at checkout and stored with the booking for audit.
