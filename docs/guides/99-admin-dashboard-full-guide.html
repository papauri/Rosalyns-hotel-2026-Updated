1. Getting started

Roles

Role Sees
admin Everything.
manager Everything except destructive admin actions (DB tools, role edits).
receptionist Bookings, payments, guest details, calendar, room service.
restaurant_staff POS Till, restaurant orders.
chef KDS only (locked-in mode).
bar_staff BDS only.
coffee_staff CDS only.
room_service Room-service dashboard, in-house bookings.

maintenance Maintenance schedules + room dashboard (out-of-service flag).
Permissions can be overridden per-user at Users → Edit → Permissions without changing the role.

Sign-in security

  • 5 failed attempts → 15 min lockout per account.
  • 10 failed attempts from the same IP → 1 hour IP block.
  • Password reset uses one-time hashed tokens, valid for 1 hour.
  • Every action (login, logout, password change, role change) logged in admin_activity_log.

Packages & Rate Plans

Room Packages /admin/packages.php

  • Create add-on packages guests can select during booking: honeymoon, half-board, airport transfer, etc.
  • Pricing models: per night, per stay, or per person per night.
  • Configure inclusions (bullet list), Font Awesome icon, description, sort order, and a featured flag for homepage promotion.
  • Scope to all room types or specific types; auto-generates a URL slug for deep-linking.

Dynamic Rate Plans /admin/rate-plans.php

  • Six plan types: seasonal, weekend, length-of-stay discount, last-minute, early-bird, and promotion.
  • Adjustments are percentage or fixed; set active date ranges, minimum/maximum nights, specific days of the week, and booking lead-time windows.
  • Priority ordering decides which plan wins when multiple plans match; is_stacking controls whether plans compound.
  • Scope to all rooms or specific room types; disable/enable without deleting.
Rate plans run automatically at booking time — no manual discounting needed. Review plans before peak season to ensure they are not stacking unexpectedly.

4. Calendar & individual rooms

  • /admin/calendar.php — colour-coded month view of every individual room's availability, bookings, and blocked dates at a glance.
  • /admin/individual-rooms.php — manage physical room instances (e.g. "Executive 101"). Set per-room occupancy tier overrides, child price multiplier, floor, notes, amenities, and photos. All status changes logged to room_maintenance_log.
  • /admin/room-dashboard.php — real-time housekeeping status board. Quick-action buttons: Mark Clean, Pass Inspection, Fail Inspection (with reason). KPI bar: check-outs today, check-ins today, rooms by status.
  • /admin/room-maintenance.php — priority-based maintenance task system (urgent / high / medium / low). Full lifecycle: pending → in_progress → completed → verified → cancelled. Supports recurring schedules and staff assignment with workload tracking.
  • /admin/blocked-dates.php — block availability at room-type level or individual-room level; single date or multiple dates; block types include maintenance, event, VIP hold. Unblock by ID.
  • /admin/room-management.php — edit room types: pricing per occupancy, child multiplier, max guests, amenities, photos, video.

5. Payments & invoices

  • /admin/payments.php — every payment row with filters by date, method, status, booking type, and free-text search (searches reference, guest name, email, phone, transaction ID, and amount). Analytics strip shows gross collected, VAT, pending receivables, and refund totals — all reflecting the active filters. CSV export available.
  • /admin/payment-add.php — record a payment against a booking. Supports document generation (invoice, receipt, quotation) at the same time. Idempotency protection prevents accidental duplicate submissions.
  • /admin/payment-refund.php — refund a previous payment with reason. Choose cash refund (money returned) or credit note (issue a CN instead). Booking balance recalculates automatically.
  • /admin/payment-details.php?id=… — full record + invoice download + audit log.
  • /admin/invoices.php — every payment as an invoice. KPI tiles: Paid & Closed (non-refund completed rows), Outstanding (pending/partial excluding pending refunds), Generated count, Refunded (identified by payment_type = 'refund'). Receivables aging panel buckets unpaid invoices by days since creation — 0–30, 31–60, 61–90, and 90+ days.
  • /admin/receipts.php — receipt register with bulk PDF backfill, email, and WhatsApp sending per row. Editable email and WhatsApp templates.
  • /admin/credit-notes.php — issue, apply, void, and re-send Credit Notes. Credit notes are used when a refund is owed but cash cannot be returned immediately (e.g. early checkout, service issue, goodwill). Each CN carries a sequential number (CN-YYYY-NNNNNN), a face value, a VAT breakdown, an optional expiry date, and a running balance. Applying a CN against a booking inserts a credit_note payment row and decrements the CN balance — the entire operation is wrapped in a database transaction with a row-level lock to prevent double-application. Only active or partially-applied CNs can be applied or voided.
  • /admin/quotations.php — manage price proposals sent before payment is collected. Statuses: Sent / Accepted / Expired (auto) / Declined. Permanent audit trail — quotes are never deleted.
Invoice and credit-note numbers are sequential and permanent — they can never be edited. Re-sending a document is always allowed; only the file content regenerates, the number is preserved.
Credit note settings: expiry period (credit_note_expiry_months) and VAT rate live in Booking Settings. Set credit_note_expiry_months to 0 for no expiry.

6. POS / KDS / BDS / CDS

See: POS · KDS · BDS · CDS.

Manager extras

  • Void any order with reason ≥ 8 chars — works at any stage; restores stock for any items already marked Ready on a station.
  • Cancel before prep — cashiers can cancel an order themselves via the POS Tabs tray if all items are still pending (no station has started). No stock is restored because none was deducted yet.
  • Close shift override with variance reason ≥ 5 chars.
  • Stations can send direct notes back to POS from ticket cards; POS shows and sounds notification alerts for new direct replies.
  • KDS/BDS/CDS ticket helpers show real fired-time context (for example, Late — fired 14:32) to improve runner communication.
  • Critical action buttons in POS and display stations use short click-lock loaders to reduce accidental double-taps during rush.
  • Stock deduction is deferred — stock deducts when KDS/BDS/CDS marks each item Ready, not when the order fires. Cancels before prep cost no stock.

Order Lifecycle Viewer /admin/order-lifecycle.php?id=…

A dedicated read-only audit page for any single order. Access it from:

  • Stock Orders list → order reference link.
  • KDS / BDS / CDS ticket footer → Log button (opens new tab).
  • POS → Tabs tray → Details → Lifecycle link (admin/manager only).
  • POS → Tabs tray → Details modal — shows an inline Order Lifecycle track (Placed → Fired → Ready → Served → Paid) with timestamps and colour-coded milestone dots without leaving the POS.

The page shows: metrics bar (placed/fired/ready/served/paid times + total cycle), all line items with per-item kitchen timestamps, a chronological activity timeline combining audit events and KDS events (stock deductions, bumps, voids), the linked payment row, and a void banner for cancelled/voided orders.

Action Role Conditions
Cancel order admin · manager Status placed/new; no item has been started yet (all still pending on station).
Void order admin only Status paid or completed. Restores stock for Ready items, cancels payment, clears station boards.

12. Gym & guest services

Gym Inquiries /admin/gym-inquiries.php

  • Inbox for fitness centre membership leads submitted via the public /gym.php page.
  • Status pipeline: new → contacted (sends notification email) → converted (sends member welcome email). Each transition is logged.

Content management

  • /admin/page-management.php — enable/disable any public page; control nav visibility, sort order, and icon. Core pages (index, booking-confirmation, review-confirmation, submit-review) are protected from being disabled — the system rejects the toggle with a clear message rather than silently breaking those flows. Safe path validation prevents traversal attacks. A confirmation modal replaces any browser confirm() dialog, and every toggle is audit-logged to system_event_log.
  • Feature toggle system — Events and Guest Services pages can be independently enabled or disabled from /admin/booking-settings.php (Service Modules section). When a module is off the public page redirects gracefully, the nav link is hidden, and cards for that module are removed from any fallback sections.   • /admin/station-settings.php — set open/close times (24 h) for Kitchen, Bar, and Coffee Bar. Handles cross-midnight stations. These windows drive the KDS production reports and define each station's business day.

14. Reviews

/admin/reviews.php — moderate guest reviews left via /submit-review.php. Approve, reply, or hide. Approved reviews appear on the public homepage.

Guest review actions

  • Approve — makes the review visible on the public homepage carousel.
  • Reply — attach a management response visible below the review on the homepage.
  • Hide / Reject — removes the review from public view without deleting the record.
  • Filter by status (Pending / Approved / Rejected) or search by guest name, email, or comment text.
  • Ratings are broken down by category: Overall, Service, Cleanliness, Location, Value.

Web Feedback Importer

A search panel at the top of the reviews page lets you pull public mentions of the hotel from the web and social platforms, then import them as pending reviews for moderation.

  • Enter the hotel name and location (defaults: Rosalyn's Beach Hotel, Mangochi Malawi).
  • Choose how many results to fetch (3–20) and select Feedback Type: Positive (praise, recommendations) or Negative (complaints, criticisms).
  • Click Find Web Feedback — the system searches public web snippets and social platforms including TikTok, Facebook, Instagram, and X/Twitter.
  • Results appear as cards showing the source, a sentiment badge (Positive or Negative), a star rating estimate, and the full snippet text.
  • Click Import on any card to save it as a pending review in the system. You can then approve, reply to, or reject it like any guest-submitted review.
  • Duplicate snippets are automatically detected — if a snippet is already in the system the Import button is replaced with Already saved.
Moderation first. All imported reviews land in Pending status regardless of sentiment — nothing goes public until a manager approves it. Negative feedback is valuable for identifying service gaps and should not be deleted; use the Reply field to acknowledge it publicly.

15. Page, footer & section content

Page Management /admin/page-management.php

  • Enable, disable, and reorder every public page from a single table.
  • Core system pages (index, booking-confirmation, review-confirmation, submit-review) cannot be disabled — the toggle is blocked with a descriptive error message.
  • Every toggle is confirmed through an admin modal (no browser confirm()) and written to system_event_log with the page name, new state, and acting user.
  • When adding a new page you can check Create PHP scaffold to have the system generate a complete Japandi-styled PHP skeleton in the webroot; the file path field auto-populates from the page key you type.

Section Headers & Page Hero Text /admin/section-headers-management.php

A two-tab CMS editor that controls all text on every public page.

Tab 1 — Page Hero Text

  • Every public page has its own hero banner card with fields for: Hero Title, Hero Subtitle, Description, Primary Button Text, and Primary Button Link.
  • All 9 pages are displayed with their edit fields always open — no toggle required. Scroll to the page you want, edit, and click Save Hero Text.
  • Use the Jump to page dropdown to filter the list to a single page instantly.
  • Toggle the Active checkbox to enable or disable a page's hero banner.
  • Use Add Hero for New Page to create a hero entry for any page not yet in the system.

Tab 2 — Section Headers

  • CMS editor for every section label, heading, subtitle, and description on every public page.
  • Use the Filter by page dropdown to show only one page's sections — the page filter preserves your tab position so you stay on the Sections tab after filtering.
  • Toggle sections active/inactive individually.
  • Revert to Defaults (Danger Zone at the bottom) wipes all overrides and re-seeds from built-in defaults. Cache is cleared on every save.

Footer Management /admin/footer-management.php

Three-tab interface giving full control over every part of the public footer:

Tab 1 — Footer Links

  • All footer navigation columns are managed here. Each link belongs to a named column (e.g. Guest Services, About Hotel).
  • Each link has a primary URL (used on the homepage, typically a hash anchor like #rooms) and an optional secondary URL (used on all other pages, typically a full path like rooms-gallery.php). The footer selects the correct one automatically.
  • Toggle visibility per link, set display order, or delete. A column with no active links disappears from the footer automatically.
  • Click Add next to any column to open a pre-filled modal; or use the Add New Footer Link form below with the column datalist for quick lookup.

Tab 2 — Policies & Modals

  • Each policy appears as a click-to-open pop-up modal in the footer. CRUD: slug, title, summary, full content, display order, active/inactive.
  • The slug links the footer link to the matching modal (e.g. slug faqs links to the FAQs modal).
  • Policy content supports DB tags — dynamic placeholders that are replaced with live database values when the footer renders. Type {{ in any policy field to trigger the tag autocomplete dropdown.

Tab 3 — Contact & Social

  • Edit phone, email, address, working hours, Facebook, Instagram, Twitter/X, and LinkedIn URLs directly. Changes go live immediately after saving (cache is cleared).
  • Copyright text and design credit line at the bottom of the footer are also editable here.

DB Tags — dynamic content in footer text

Any saved text in footer policies, copyright line, or credits can include {{tag}} tokens. They are resolved to live site_settings values at render time — no redeploy needed.

Use ↓↑ to navigate, Enter or Tab to insert, Esc to dismiss. Or click any tag chip in the DB Tags reference panel at the top of the page to insert at the cursor.

17. Reports & analytics

Full step-by-step guide: → Guide 14: Reports & End of Day
  • /admin/reports.php — revenue, occupancy, RevPAR, ADR, by date range. CSV export.
  • /admin/accounting-dashboard.php — the accountant's command centre for any date range. Panels: overall financial summary (gross collected, net excl. VAT, VAT collected net of returned VAT, pending receivables, refunds issued, pending refunds); revenue by source; payment method breakdown; refund reasons; recent 20 payments; all-time outstanding balances; POS analytics (revenue by order type, gross margin vs COGS, 14-day daily trend); compliance checks (missing receipts, invoices without numbers, POS orders without ledger); quotation pipeline; credit note stats; VAT Settings form.
  • /admin/pos-accounting.php — POS cashier shift reconciliation. Pick a business date and the system shows every cashier's expected totals (cash, mobile money, card) derived from paid orders. The accountant enters the declared amounts from the physical drawer, reviews each individual sale in a collapsible per-cashier drawer (add per-order notes), and submits to close selected shifts. Variance (Declared − Expected) is colour-coded: green = match, amber = small difference, red = shortfall. A Settled from tabs figure shows orders placed before the business day but paid during it. Shift closes are written to stock_shift_closes and audited in stock_order_audit within a single database transaction. Re-opening a closed date is not permitted — contact a developer if correction is needed.
  • /admin/end-of-day-report.php — daily operations snapshot: arrivals vs completed, departures, stayovers, revenue per category, occupancy %, trend vs previous day with colour-coded indicators. Designed to be shared with ownership each evening.
  • /admin/kds-report.php — per-station production report for any date using each station's configured business window. Shows every served/voided item with full KDS timestamps, top items by count, avg prep time. CSV export & email delivery.
  • /admin/visitor-analytics.php — public-site traffic: pages visited, device breakdown, geographic origin. Date range filters. Purge tool for old records.

19. Cache, audit & security

  • /admin/cache-management.php — toggle cache types on/off; clear page cache, query cache, settings cache with before/after file counts reported.
  • admin_activity_log — every login, password reset, role change.
  • housekeeping_audit_log + maintenance_audit_log — every status change with old → new + reason.
  • booking_timeline_logs — every status change on a booking.
  • /admin/system-logs.php — system_event_log viewer for all rh_log_event() entries across every module.

20a. Backups & offline log

  • /admin/backup-management.php — on-demand database backup (scripts/backup_database.php). Lists available backups by date/size. Admin-only download as .sql.gz and restore from a selected backup.
  • /admin/offline-log.php — every POS/KDS action queued offline (load shedding / poor connectivity) and replayed when connection returned. Shows queue lag, replayed action count, per-user and per-endpoint breakdown. Useful for shift reconciliation.
Run an on-demand backup before any DB migration or major configuration change. Download it to off-site storage monthly.

20. Troubleshooting cheatsheet

Symptom Likely cause Fix
Login screen rejects valid password Account locked (5 fails) Wait 15 min OR use Forgot password.
KDS shows nothing Station role mismatch Sign in as chef / bar_staff / coffee_staff.
POS won't fire to KDS Item not routed Open Menu → Item → set Station.
Stock count drifted Untracked void Cross-check Stock Variance & recipe.

Guest got duplicate confirmation Multiple status changes Expected — one email per status change.
Invoice PDF missing TCPDF font missing Falls back to HTML; check logs/.
Restore button missing Not logged in as admin Only admin role can restore — sign in as admin.
Rate plan not applying Priority clash or wrong date range Check rate-plans.php — confirm date range covers the stay and priority ordering.
Footer tag not resolving (shows {{tag}} literally) Tag typed incorrectly or setting value is empty Check the Tags panel in footer-management.php — the live value is shown next to each chip. If blank, update the setting in Booking Settings or Site Settings first.
Events or Guest Services page returns “coming soon” Module disabled in Service Modules Go to booking-settings.php → Service Modules → enable the relevant toggle.

Final reminders

Every action is logged. Sign in as yourself.
  • Never delete — always cancel or void with a reason.
  • Cache updates on every save; if the public site looks stale, use Cache → Clear page cache.
  • The test scripts under /scripts/ are safe to re-run any time you suspect drift.
